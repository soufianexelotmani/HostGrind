# HostGrid — Master Prompt pour Codex

## Mission
Agis comme ingénieur full-stack senior. Implémente HostGrid, PMS SaaS privé pour conciergeries immobilières marocaines. Travaille dans le repository existant : `frontend/` (Angular 21) et `backend/` (HostGrid.Api, ASP.NET Core 10 Web API avec controllers). Inspecte les fichiers, versions, git status et instructions AGENTS.md avant toute modification. Ne recrée pas les projets, ne remplace pas le squelette, ne supprime pas les modifications utilisateur. Si un prérequis manque, documente-le. Ne prétends jamais avoir exécuté une commande non exécutée.

Lis intégralement les sept fichiers compagnons à la racine : AGENTS.md, ARCHITECTURE.md, DATABASE_DESIGN.md, BUSINESS_RULES.md, DESIGN_SYSTEM.md, IMPLEMENTATION_PLAN.md, AZURE_DEPLOYMENT.md. Ils font partie du cahier des charges. Les décisions explicites de ces documents priment sur les conventions des templates. En cas de contradiction, signale-la avant d'implémenter.

## Périmètre V1
- SaaS multi-conciergeries, une seule active initialement, plusieurs propriétaires et biens. Trois rôles : SuperAdmin global, Manager de sa conciergerie, Owner de ses seuls biens. Comptes créés manuellement, aucun signup public, abonnement, paiement SaaS, rôle employé ou portail voyageur.
- Web responsive et PWA installable online-only, français, anglais, arabe RTL ; MAD, fuseau Africa/Casablanca.
- Biens : studio, appartement, villa, maison, riad, chambre ; un propriétaire par bien ; contrats simples, taux de commission configurable (20 % par défaut), inventaire simple, photos et contrats privés, tarifs saisonniers/weekends/périodes personnalisées.
- Réservations Airbnb, Booking.com, direct : **100 % manuelles**. Aucun iCal, scraping, API externe, synchronisation de tarifs ou calendrier en V1. Référence externe facultative. Calendrier global/par bien jour/semaine/mois, filtres, blocages manuels, conflits stricts. Clients simples, check-in/out manuels, paiements partiels, annulations et remboursements tracés.
- Finance : revenus nets après frais plateforme, commission sur ce net avant charges, charges supportées par le propriétaire. Clôture mensuelle manuelle par bien, définitive ; régularisations ultérieures, versements et avances. Voir BUSINESS_RULES.md pour les calculs et tests.
- Charges : catégories personnalisables, récurrence automatique, justificatif obligatoire à confirmation, paiements partiels, avances/remboursements complets, échéances et alertes, une charge par bien, validation directe manager. Aucun fournisseur dédié, charge commune ou dépense interne conciergerie.
- Opérations : nettoyage automatique après checkout confirmé et manuel, checklists personnalisées par bien, intervenants externes simples sans compte, maintenance simple sans préventif, tâches liste/Kanban/calendrier, photos facultatives, charges liées après confirmation, blocage manuel, notifications internes et email.
- Demandes propriétaires : maintenance, justificatif de charge, versement, blocage de dates, modification du bien, autre ; messages, statut, historique ; aucune modification directe du bien par Owner.
- Dashboards distincts par rôle, KPI de base (revenus, charges, commissions, bénéfice, occupation), filtres complets, comparaisons périodes/biens/plateformes, graphiques interactifs, actualisation automatique après mutations et périodique, widgets personnalisables. Exports PDF/Excel et rapports générés manuellement. SuperAdmin : utilisateurs, organisations, finance globale, audit et santé système réelle.

## Stack imposée
Angular 21 standalone, Signals, RxJS, Reactive Forms, PrimeNG + Tailwind CSS 4, Transloco, Lucide, ECharts, FullCalendar standard, Angular CDK, Angular Service Worker. ASP.NET Core 10, un seul projet applicatif backend, controllers, services, repositories spécifiques, DTOs, mappers, validators, EF Core SQL Server Code First, Identity/JWT, FluentValidation, Mapperly ou mapping manuel explicite, Serilog, OpenAPI/Scalar, QuestPDF, ClosedXML, MailKit, Hosted Services, IMemoryCache. Tests séparés autorisés. Vérifie compatibilité et licences avant installation ; ne change pas de stack sans expliquer et demander validation si bloquant.

## Exécution
Commence par la phase 1 d'IMPLEMENTATION_PLAN.md. Implémente par tranches verticales, sans générer toutes les fonctionnalités en une opération non vérifiée. À chaque phase : inspecter, planifier, coder, compiler, tester, corriger, documenter. Maintiens `docs/PROGRESS.md` (statut, commandes, résultats réels, migrations, limites, prochaine phase). Arrête-toi à un checkpoint si une décision utilisateur, un secret, une licence ou un service externe est nécessaire. Ne déploie rien ni ne provisionne Azure sans autorisation explicite. Ne fais pas de commit/push destructif ou automatique sans accord.

## Définition de terminé
Fonctionnalités réellement connectées à SQL Server et à l'API ; aucune fausse donnée en production, aucun bouton inerte, aucun TODO cachant une fonctionnalité annoncée. Autorisation serveur systématique, isolation tenant/owner, règles financières testées, migrations reproductibles, UI accessible FR/EN/AR, tests et documentation. Les mocks sont limités aux tests/démonstrations explicitement identifiées. Fournis README local, guide utilisateur, ERD, documentation API et déploiement. Rapporte honnêtement tout échec ou fonctionnalité non terminée.
